Source conflicts/decisions:

- Earlier HTML functions and default seeds describe behavior superseded by later scripts. In particular scripts 77–79 and 83–85 take precedence for signed adjustments, partial trader sales, remaining purchases and ledger behavior. Original prototype seeds were not imported.
- Script 64's browser password mechanism is replaced by real Laravel authentication. At the user's later request, staff-to-owner workspace changes now verify the authenticated owner's current login password on the server. The selected view persists in the session; staff view enforces clerk permissions and account filtering. Returning to staff requires no password. Real clerk accounts cannot elevate.
- The source sometimes represents an unweighed quantity as numeric zero plus a `weightKnown` flag. MySQL stores unknown quantities as NULL and preserves the flag in the read projection; explicitly recorded zero remains distinct. Unknown raw bag counts are NULL, not invented proportional counts.
- The source has physical master deletion in some places. This implementation uses inactivation to retain references and history. Confirm the wording/behavior of every delete control during parity review; currently some labels still say delete.
- Source loan policy is daily simple accrual at monthly 3%/4%, divided by 30, with same-day interest zero. Advances and loan principal recovery are not revenue. Loan-interest recognition and purchase labor/manual charges remain excluded/unclassified under the source provisional P&L; no finalized accounting classification is asserted.
- Some source permissions are broadened by later overrides: packaging setup and direct lot adjustments are available to staff; account configuration, lending, funding, home-request issue and approvals remain owner-controlled. The source's role selector is a view switch only for an authenticated owner.
- A single InnoDB workspace lock serializes writes. This intentionally prioritizes correctness for one business workspace. No multi-branch throughput or distributed deployment acceptance is claimed.

Do not deploy this as a fully accepted replacement until these parity and acceptance checks are resolved. The only existing-data move performed was the explicitly requested local MySQL-to-MariaDB cutover, preserving all original records. Prototype browser data were not imported. No destructive reset, automatic opening balance, or production deployment was performed.
