Pwe Yon Software

အသုံးပြုထားသော နည်းပညာများနှင့် စနစ်တည်ဆောက်ပုံ

ပြုစုသည့်နေ့ — ၂၀၂၆ ခုနှစ်၊ အောက်တိုဘာလ ၂၆ ရက်

ဤစာတမ်းသည် လက်ရှိ Pwe Yon project ၏ code၊ dependency စာရင်း၊ database migration များနှင့် သိမ်းဆည်းထားသော စမ်းသပ်ရလဒ်များကို အခြေခံ၍ ရေးသားထားခြင်းဖြစ်သည်။ နည်းပညာအမည်များကို မူရင်းအတိုင်း ဖော်ပြပြီး ၎င်းတို့၏ အသုံးဝင်ပုံကို မြန်မာလို ရှင်းပြထားသည်။

၁။ Pwe Yon ကို ဘယ်လို software အဖြစ် တည်ဆောက်ထားသလဲ

Pwe Yon သည် browser မှတစ်ဆင့် အသုံးပြုရသော Web Application ဖြစ်သည်။ ကုန်လက်ခံခြင်း၊ အဝယ်အတည်ပြုခြင်း၊ အရောင်း၊ ကုန်ထုတ်ပေးခြင်း၊ ငွေပေးချေ/လက်ခံခြင်း၊ ကုန်လက်ကျန်နှင့် အစီရင်ခံစာများကို ဆောင်ရွက်နိုင်ရန် တည်ဆောက်ထားသည်။

စနစ်ကို အသုံးပြုသူမြင်ရသော မျက်နှာပြင် (Frontend)၊ စည်းမျဉ်းများစစ်ဆေးပြီး အလုပ်လုပ်ပေးသော server အပိုင်း (Backend) နှင့် အချက်အလက်သိမ်းဆည်းရာ Database ဟူ၍ အဓိက အပိုင်းသုံးပိုင်းဖြင့် ဖွဲ့စည်းထားသည်။

၂။ ဘယ် language နှင့် framework တွေ သုံးထားသလဲ

နည်းပညာ — Pwe Yon တွင် အသုံးပြုပုံ

PHP — Backend အတွက် အသုံးပြုသော programming language ဖြစ်သည်။ လုပ်ငန်းစည်းမျဉ်းများ၊ ငွေကြေးတွက်ချက်မှု၊ ကုန်လက်ကျန်ပြောင်းလဲမှုနှင့် login စစ်ဆေးမှုများကို လုပ်ဆောင်သည်။ မှတ်တမ်းတင်ထားသော runtime version သည် PHP 8.5.12 ဖြစ်သည်။

Laravel 13.38.0 — PHP ဖြင့်ရေးထားသော web framework ဖြစ်သည်။ URL လမ်းကြောင်းများ၊ request စစ်ဆေးခြင်း၊ session/login၊ database ချိတ်ဆက်ခြင်းနှင့် migration များကို စနစ်တကျ စီမံပေးသည်။ လက်ရှိ composer.lock တွင် ဤ version ကို သတ်မှတ်ထားသည်။

HTML + Blade — စာမျက်နှာ၊ form၊ table နှင့် ခလုတ်များ၏ ဖွဲ့စည်းပုံကို HTML ဖြင့် ပြုလုပ်ထားသည်။ Laravel ၏ Blade template က login ဝင်ထားသူနှင့် သက်ဆိုင်သော server data ကို မျက်နှာပြင်သို့ ထည့်ပေးသည်။

CSS — အရောင်၊ စာလုံး၊ အရွယ်အစား၊ အကွာအဝေးနှင့် စာမျက်နှာအပြင်အဆင်များကို သတ်မှတ်သည်။ ပေးထားသော မူရင်း interface ၏ ပုံစံနှင့် မြန်မာစာ label များကို ဆက်လက်အသုံးပြုထားသည်။

JavaScript — Browser အတွင်း menu ပြောင်းခြင်း၊ form အလုပ်လုပ်ခြင်း၊ ကြိုတင်တွက်ချက်ပြခြင်း၊ save/loading အခြေအနေပြခြင်းနှင့် Laravel server ထံ data ပို့ခြင်းတို့ကို လုပ်ဆောင်သည်။

SQL / Laravel Database API — MariaDB မှ data ရယူခြင်း၊ ထည့်ခြင်းနှင့် ပြင်ဆင်ခြင်းအတွက် အသုံးပြုသည်။ Code တွင် Laravel Query Builder နှင့် အသုံးပြုသူအတွက် Eloquent model ကို အသုံးပြုထားသည်။

Laravel နှင့် Blade သည် သီးခြား programming language များ မဟုတ်ဘဲ PHP အခြေပြု framework နှင့် template နည်းပညာတို့ ဖြစ်သည်။ HTML သည် စာမျက်နှာဖွဲ့စည်းပုံအတွက်ဖြစ်ပြီး CSS သည် အလှဆင်ပုံအတွက် ဖြစ်သည်။

၃။ ဘယ် database ကို သုံးထားသလဲ

လက်ရှိ အဓိက database သည် XAMPP တွင်ပါဝင်သော MariaDB 10.11.16 ဖြစ်သည်။ အသုံးပြုသူ၏ ရွေးချယ်မှုအရ ၂၀၂၆ ခုနှစ်၊ အောက်တိုဘာလ ၂၆ ရက်တွင် မူလ MySQL 8.4.13 မှ MariaDB သို့ ပြောင်းရွှေ့ထားသည်။ လုပ်ငန်းဆိုင်ရာ table များတွင် InnoDB storage engine ကို ဆက်လက်အသုံးပြုထားသည်။ InnoDB က ဆက်စပ် data များကို တစ်ပြိုင်တည်း မှန်ကန်စွာသိမ်းခြင်းနှင့် တစ်ချိန်တည်း လုပ်ဆောင်မှုများကို ထိန်းချုပ်ခြင်းတို့ကို ပံ့ပိုးပေးသည်။

Database အမည် — အသုံးပြုရသည့် ရည်ရွယ်ချက်

pweyon — Application အသုံးပြုစဉ် လုပ်ငန်းအချက်အလက်များကို သိမ်းဆည်းရန်။

pweyon_test — စမ်းသပ် data များဖြင့် automated test နှင့် browser test ပြုလုပ်ရန်။ Application data နှင့် သီးခြားခွဲထားသည်။

အထက်ပါနှစ်ခုသည် MariaDB server တစ်ခုအတွင်းရှိ database သီးခြားနှစ်ခု ဖြစ်သည်။ လက်ရှိ local setup တွင် 127.0.0.1၊ port 3306 ကို အသုံးပြုထားသည်။ Laravel ၏ DB_CONNECTION=mariadb ဖြင့် ချိတ်ဆက်ထားပြီး application နှင့် test အတွက် သီးခြားလုပ်ပိုင်ခွင့်ကန့်သတ်ထားသော database user များကို အသုံးပြုထားသည်။

Database ကြည့်လိုလျှင် XAMPP တွင် Apache နှင့် MySQL module ကို ဖွင့်ပြီး http://localhost/phpmyadmin/ သို့ ဝင်ကာ pweyon ကို ရွေးနိုင်သည်။ XAMPP control panel ပေါ်က MySQL ဟူသောအမည်သည် ဤစက်တွင် MariaDB server ကို ရည်ညွှန်းသည်။ မူလ data နှင့် owner အကောင့်ကို ရွှေ့ပြောင်းပြီး တိုက်စစ်ထားကာ MySQL data အဟောင်းနှင့် backup ကို ပြန်လည်ရယူနိုင်ရန် ထိန်းသိမ်းထားသည်။

Database တွင် users၊ ကုန်သည်/ဝယ်သူ၊ ကုန်ပစ္စည်း၊ ဂိုဒေါင်၊ ငွေသိမ်းရာ၊ လုပ်ငန်းစာရွက်စာတမ်း၊ ကုန်လက်ကျန်၊ ကုန်အဝင်/အထွက်၊ ငွေပေးချေမှု၊ အကြိုငွေနုတ်ယူမှု၊ stock စစ်ဆေးမှုနှင့် လုပ်ဆောင်ချက်မှတ်တမ်းများကို ဆက်စပ် table များဖြင့် သိမ်းထားသည်။

၄။ မျက်နှာပြင်ကနေ database ထိ ဘယ်လို အလုပ်လုပ်သလဲ

အသုံးပြုသူ → HTML / JavaScript မျက်နှာပြင် → Laravel server → MariaDB → သိမ်းပြီးရလဒ် → မျက်နှာပြင်

ဥပမာ — ကုန်လက်ခံစာရင်းတစ်ခု သိမ်းသည့်အခါ အောက်ပါအဆင့်များဖြင့် လုပ်ဆောင်သည်။

• အသုံးပြုသူက ကုန်သည်၊ ကုန်ပစ္စည်း၊ ဂိုဒေါင်နှင့် အလေးချိန်တို့ကို form တွင် ဖြည့်ပြီး သိမ်းမည့်ခလုတ်ကို နှိပ်သည်။

• JavaScript က သက်ဆိုင်ရာလုပ်ဆောင်ချက်နှင့် ဖြည့်ထားသော data ကို HTTP request ဖြင့် Laravel server သို့ ပို့သည်။ API တွင် JSON data ပုံစံကို အသုံးပြုသည်။

• Laravel က login၊ လုပ်ပိုင်ခွင့်၊ မဖြစ်မနေဖြည့်ရန်လိုသော အချက်များနှင့် လုပ်ငန်းစည်းမျဉ်းများကို စစ်ဆေးသည်။

• Server က လိုအပ်သော တန်ဖိုးများကို တွက်ချက်ပြီး ဆက်စပ်စာရင်းများကို MariaDB တွင် transaction ဖြင့် သိမ်းသည်။ အမှားဖြစ်လျှင် ဆက်စပ်သိမ်းဆည်းမှုများကို နောက်ပြန်ပြန်ပယ်သည်။

• သိမ်းဆည်းမှုအောင်မြင်ပြီးနောက် server က အတည်ပြုထားသော data ကို ပြန်ပို့၍ မျက်နှာပြင်ကို ပြန်လည်ပြသသည်။ စာမျက်နှာကို refresh လုပ်သည့်အခါလည်း server မှ သိမ်းထားသော data ကို ပြန်ရယူသည်။

လက်ရှိ ချိတ်ဆက်ထားသော အဓိကလမ်းကြောင်းများမှာ /login၊ /api/state၊ /api/commands နှင့် /api/reports/{kind} တို့ဖြစ်သည်။ JavaScript ၏ fetch ဖြင့် server ကို ဆက်သွယ်ထားသည်။

၅။ ငွေစာရင်းနှင့် ကုန်လက်ကျန်ကို ဘယ်လို ထိန်းထားသလဲ

• ငွေပမာဏများနှင့် အလေးချိန်များအတွက် MariaDB DECIMAL နှင့် PHP BCMath ကို အသုံးပြုထားသည်။ ဒဿမကိန်းများကို စနစ်တကျ တွက်ချက်နိုင်ရန် ဖြစ်သည်။ Browser တွင်ပြထားသော စုစုပေါင်းကိုသာ ယုံကြည်၍ သိမ်းခြင်းမပြုဘဲ server တွင် ပြန်တွက်သည်။

• Transaction ကို အသုံးပြုထားသဖြင့် စာရွက်စာတမ်း၊ ကုန်လက်ကျန်နှင့် ငွေလှုပ်ရှားမှုတို့ကို ဆက်စပ်စွာ သိမ်းနိုင်သည်။ တစ်ပိုင်းအောင်မြင်ပြီး ကျန်တစ်ပိုင်းပျက်သည့် မညီမညာအခြေအနေကို ကာကွယ်ရန် ဖြစ်သည်။

• InnoDB lock နှင့် လက်ကျန်ပြန်စစ်ခြင်းကို အသုံးပြု၍ အသုံးပြုသူနှစ်ဦးက တစ်ချိန်တည်း လုပ်ဆောင်ရာတွင် ကုန်ပိုရောင်းခြင်း၊ လက်ကျန်ထက်ပို၍ ငွေလက်ခံခြင်း စသည့်အခြေအနေများကို ထိန်းထားသည်။ လက်ရှိ workspace တစ်ခုအတွင်း business write များကို အလှည့်ကျ လုပ်ဆောင်စေသည်။

• Idempotency-Key ဟုခေါ်သော request အမှတ်အသားဖြင့် တူညီသော request ကို ပြန်ပို့သည့်အခါ မူလအကျိုးသက်ရောက်မှုကို နှစ်ခါမဖြစ်စေရန် စစ်ဆေးသည်။

• ကုန်လက်ကျန်တွင် ကုန်သည်ပိုင်၊ ပွဲရုံပိုင်နှင့် ဝယ်သူပိုင်ကို ခွဲခြားထားသည်။ ပိုင်ဆိုင်မှုပြောင်းခြင်းနှင့် ဂိုဒေါင်မှ အမှန်တကယ် ကုန်ထွက်ခြင်းကို သီးခြားမှတ်တမ်းတင်သည်။

ဥပမာ — ကုန် ၁,၅၀၀ ပိဿာ လက်ခံပြီး ၅၀၀ ပိဿာကို ဝယ်သူပိုင်အဖြစ် သိမ်းပေးကာ ကျန် ၁,၀၀၀ ပိဿာကို ပွဲရုံက ဝယ်ယူလျှင် ကုန်အမှန်တကယ် မထုတ်ပေးရသေးသရွေ့ ဂိုဒေါင်ရှိ စုစုပေါင်းမှာ ၁,၅၀၀ ပိဿာပင် ဖြစ်သည်။ ဤဥပမာကို MariaDB test ဖြင့် ပြန်လည်စစ်ဆေးထားသည်။

၆။ Login နှင့် လုံခြုံရေးကို ဘယ်လိုလုပ်ထားသလဲ

• Laravel session authentication ဖြင့် login ဝင်ထားသူကို ခွဲခြားသည်။ Password ကို database တွင် hash ပြုလုပ်၍ သိမ်းထားသည်။

• Owner နှင့် Clerk တို့၏ လုပ်ပိုင်ခွင့်ကို server ဘက်တွင် စစ်ဆေးသည်။ Browser ထဲမှ role တန်ဖိုးကို ပြောင်းခြင်းဖြင့် လုပ်ပိုင်ခွင့် တိုးယူ၍ မရစေရန် စစ်ဆေးထားသည်။

• Clerk ကြည့်ခွင့်မရှိသော ငွေသိမ်းရာ data များကို server က ဖယ်ထုတ်ပြီးမှ ပြန်ပို့သည်။

• Request validation၊ Laravel ၏ CSRF/request-forgery ကာကွယ်မှုနှင့် login ကြိုးစားမှုအကြိမ်ရေကန့်သတ်ခြင်းတို့ ပါဝင်သည်။

• Database ချိတ်ဆက်မှုဆိုင်ရာ လျှို့ဝှက်တန်ဖိုးများကို .env ဖိုင်တွင် သီးခြားထားသည်။ မျှဝေရန် .env.example တွင် နမူနာနေရာဖြည့်တန်ဖိုးများသာ ထည့်ထားသည်။

၇။ မူရင်း HTML နှင့် localStorage ကို ဘယ်လိုပြောင်းထားသလဲ

ပေးထားသော မူရင်း HTML interface ကို Laravel Blade နှင့် ချိတ်ဆက်ထားပြီး မူရင်း CSS၊ JavaScript၊ မြန်မာစာ label နှင့် လုပ်ငန်းမျက်နှာပြင်များကို ဆက်လက်အသုံးပြုထားသည်။ Backend နှင့်ချိတ်ဆက်ရန် server-bootstrap.js၊ server-bridge.js နှင့် server-reports.js တို့ကို ဖြည့်စွက်ထားသည်။

လုပ်ငန်း data ၏ အဓိကသိမ်းဆည်းရာမှာ MariaDB ဖြစ်သည်။ localStorage ကို ဘာသာစကားကဲ့သို့ မျက်နှာပြင်ဆိုင်ရာ preference များအတွက်သာ အသုံးပြုနိုင်စေရန် ပြင်ဆင်ထားသည်။ Server request ပျက်သည့်အခါ browser ထဲတွင် လုပ်ငန်းစာရင်းကို အစားထိုးသိမ်းသည့် fallback မရှိပါ။ ချိတ်ဆက်မပြီးသေးသော legacy save လုပ်ဆောင်ချက်များကို တားထားပြီး ဆက်လက်စစ်ဆေးရန် မှတ်တမ်းတင်ထားသည်။

၈။ ဖွံ့ဖြိုးရေးနှင့် စမ်းသပ်ရေး tool များ

Tool — အသုံးပြုပုံ

Composer — PHP/Laravel အတွက် လိုအပ်သော package များနှင့် ၎င်းတို့၏ version များကို စီမံရန်။

Node.js + npm — မူရင်း HTML စိစစ်ခြင်း၊ interface asset ပြင်ဆင်ခြင်းနှင့် စမ်းသပ်ရေး script များအတွက်။ လုပ်ငန်း backend ကို PHP/Laravel ဖြင့် လည်ပတ်ထားသည်။

Laravel Migrations — Database table နှင့် ဆက်စပ်မှုများကို အဆင့်လိုက် တည်ဆောက်/ပြင်ဆင်ရန်။ စစ်ဆေးမှတ်တမ်းအရ migration ၃၀ ခု အသုံးချထားသည်။

PHPUnit — MariaDB နှင့် အမှန်တကယ်ချိတ်ဆက်၍ လုပ်ငန်းစည်းမျဉ်းများကို automated test လုပ်ရန်။ မူလ MySQL စမ်းသပ်ရလဒ်များကိုလည်း သီးခြားထိန်းသိမ်းထားသည်။

Playwright Core + Edge — Browser အစစ်တွင် login၊ form save၊ refresh နောက် data ရှိနေမှုနှင့် လုပ်ပိုင်ခွင့်များကို စမ်းသပ်ရန်။

jsdom + Laravel Pint — JavaScript/မျက်နှာပြင် အပြုအမူစမ်းသပ်ခြင်းနှင့် PHP code ပုံစံတစ်ညီတည်းဖြစ်စေရန်။

၉။ လက်ရှိပြီးစီးမှုနှင့် စမ်းသပ်ထားသည့်အခြေအနေ

၂၀၂၆ ခုနှစ်၊ အောက်တိုဘာလ ၂၆ ရက် MariaDB ပြောင်းရွှေ့မှုအပြီး စမ်းသပ်ရာတွင် PHPUnit test ၄၉ ခု၊ assertion ၁၆၉ ခု အောင်မြင်ထားသည်။ Migration တည်ဆောက်ခြင်း၊ test database တွင် rollback ပြုလုပ်ပြီး ပြန်တည်ဆောက်ခြင်းနှင့် data table ၃၂ ခုလုံး၏ မူလတန်ဖိုးများကို တိုက်စစ်ခြင်းတို့လည်း အောင်မြင်ထားသည်။

Browser စမ်းသပ်မှုတွင် Owner/Clerk login၊ ကုန်လက်ခံ၊ အဝယ်နှင့် တစ်စိတ်တစ်ပိုင်းငွေပေးချေမှု၊ ဝယ်သူပိုင်ကုန်သိမ်းခြင်း၊ နောက်မှကုန်ထုတ်ပေးခြင်း၊ နောက်မှငွေလက်ခံခြင်း၊ refresh နောက် data ပြန်ရခြင်းနှင့် လုပ်ပိုင်ခွင့်စစ်ဆေးခြင်းတို့ အောင်မြင်ထားသည်။

Application သည် local တွင် လည်ပတ်နိုင်သော အဆင့်ရှိသော်လည်း မူရင်းလုပ်ငန်းမျက်နှာပြင်အားလုံးနှင့် တစ်ခုချင်းကိုက်ညီမှု၊ အသေးစိတ် report များ၊ ရှုပ်ထွေးသော opening/settlement ပေါင်းစပ်အသုံးပြုမှုများ၊ print/export အမျိုးအစားအားလုံးနှင့် အသုံးပြုသူလက်ခံစမ်းသပ်မှု (UAT) တို့ကို ဆက်လက်စစ်ဆေးရန် ရှိနေသည်။ Production အသုံးပြုရန် အပြီးသတ်လက်ခံပြီးဟု မသတ်မှတ်ရသေးပါ။

၁၀။ Project ဖိုင်များ ဘယ်မှာရှိသလဲ

• working/pweyon — Laravel application နှင့် backend source code။

• working/pweyon/resources/views — Blade မျက်နှာပြင်ဖိုင်များ။

• working/pweyon/public/js နှင့် public/css — JavaScript နှင့် CSS asset များ။

• working/pweyon/app/Domain — လုပ်ငန်းစည်းမျဉ်း၊ တွက်ချက်မှုနှင့် report service များ။

• working/pweyon/database/migrations — Database ဖွဲ့စည်းပုံ တည်ဆောက်သည့် migration များ။

• development/tools နှင့် development/runtime — ပြန်အသုံးပြုနိုင်သော စမ်းသပ်/build/စာတမ်း tools နှင့် ၎င်းတို့ထုတ်ပေးသော ယာယီဖိုင်များ။

• reference/originals နှင့် reference/extracted — မူရင်း HTML/PDF နှင့် ၎င်းတို့မှ ခွဲထုတ်ထားသော ရည်ညွှန်းဖိုင်များ။ လက်ရှိ application request အတွင်း တိုက်ရိုက်မဖတ်ပါ။

• archive/private — ပြန်လည်ရယူရေးအတွက် ထိန်းသိမ်းထားသော အဟောင်း database/config backup များ။ မလိုအပ်သော scaffold၊ တစ်ကြိမ်သုံး script နှင့် ယာယီဖိုင်များကို အသုံးပြုသူညွှန်ကြားချက်အရ ဖျက်ပြီးဖြစ်သည်။

• docs — လုပ်ငန်းချိတ်ဆက်ပုံ၊ စမ်းသပ်ရလဒ်၊ ဆက်လက်လုပ်ဆောင်ရန်အချက်များနှင့် ပြန်ဆက်လုပ်ရန် checkpoint များ။

နည်းပညာဖွဲ့စည်းပုံ အကျဉ်း — HTML + CSS + JavaScript + Blade မျက်နှာပြင်၊ PHP + Laravel backend၊ MariaDB + InnoDB database တို့ကို ပေါင်းစပ်၍ တည်ဆောက်ထားသော Web Application ဖြစ်သည်။
